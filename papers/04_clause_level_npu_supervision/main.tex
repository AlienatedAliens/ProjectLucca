\begin{abstract}
In a prior study (\href{https://doi.org/10.5281/zenodo.23901605}{DOI: 10.5281/zenodo.23901605}), we showed that deterministic speech-regex and stem-list action supervisors reach an empirical ceiling on live language model outputs: across $N=1{,}000$ four-model completions, a 44-stem grammar supervisor caught $71.1\%$ ($128/180$) of in-vocabulary action claims but dropped to $29.5\%$ ($23/78$) on unseen verb lemmas ($58.5\%$ overall), while Structured-Output Action Contracts (SOAC) triggered spurious action frames on $13.3\%$--$16.7\%$ of conversational idioms. Replacing lexical rules with a neural classifier solves open-vocabulary generalization on isolated single sentences, yet introduces two new failure modes in edge companion deployments: (1) dGPU VRAM contention with the primary language model, and (2) severe probability dilution when a single fabricated action clause or task request is buried inside a multi-sentence response. In this paper, we present a three-classifier neurosymbolic supervision and routing architecture compiled to FP16 on an Intel AI Boost NPU ($0\text{ MB}$ dGPU VRAM, $1.22$--$2.95\text{ ms}$ mean inference latency on an Intel Core Ultra 9 275HX). By decomposing multi-sentence inputs into syntactic clauses (\texttt{split\_into\_clauses}) and applying domain-specific pooling operators---max-violation probability pooling for action-claim supervision, max-hazard lattice pooling for epistemic proof policy, and task-priority pooling for 29-class intent routing---we eliminate multi-sentence dilution without modifying the underlying 22M-parameter \texttt{DeBERTa-v3-small} weights. Across an expanded $N=2{,}022$ action-claim evaluation battery (combining the 1,000-turn 4-model corpus, 120-turn held-out v1/v2 corpus, 352 multi-sentence/implicit/adversarial probes, and 550 Hypothesis property-based fuzz cases), the clause-level NPU verifier achieves \textbf{99.26\% accuracy ($2{,}007/2{,}022$, 95\% Wilson CI: $[98.78\%, 99.55\%]$)}, \textbf{98.73\% recall ($465/471$)}, and \textbf{0.58\% FPR ($9/1{,}551$)}, outperforming the 44-stem regex baseline ($11.46\%$ recall [$54/471$], McNemar $\chi^2 = 399.04, p = 3.07 \times 10^{-89}$). On a pre-registered 150-item locked holdout (\texttt{WO42\_LOCKED\_HOLDOUT\_150}) authored by three isolated subagents and graded by blinded raters ($\kappa = 1.000$), the three NPU classifiers achieve $145/150$ ($96.67\%$) single-pass accuracy and $150/150$ ($100.0\%$) after adding a temporal-keyword guard against \texttt{schedule\_event} false triggers. Finally, across a live 100-turn end-to-end evaluation spanning all four local Gemma-4 GGUF checkpoints (\texttt{26B-A4B}, \texttt{12B}, \texttt{E4B}, \texttt{E2B}), the system achieves \textbf{100/100 (100.0\%)} functional coherence, intercepting $28/28$ adversarial false action claims with $0/16$ false alarms on benign code and JSON explanations.
\end{abstract}

\section{Introduction}
\label{sec:intro}
An autonomous local agent that executes code, modifies workspace files, and queries external networks must satisfy two distinct honesty invariants. First, it must not poison its own long-term memory by storing unverified assistant narration as grounded fact. In our first study \cite{maxwell2026poisoning} (\href{https://doi.org/10.5281/zenodo.23901452}{DOI: 10.5281/zenodo.23901452}) and our five-layer memory report \cite{maxwell2026fivelayer} (\href{https://doi.org/10.5281/zenodo.23901683}{DOI: 10.5281/zenodo.23901683}), we enforced this storage invariant through six HKDF-derived HMAC-SHA256 signers and SQLite triggers that partition autobiographical recollections (\texttt{memory\_eligible=1, grounding\_eligible=0}) from verified facts (\texttt{grounding\_eligible=1}).

Second, the agent must not claim in live speech or text that it has executed a state-modifying action when no corresponding \texttt{ToolReceipt} exists in the current turn. In our second study \cite{maxwell2026evasion} (\href{https://doi.org/10.5281/zenodo.23901605}{DOI: 10.5281/zenodo.23901605}), we evaluated two deterministic mechanisms for enforcing this runtime output invariant:
\begin{enumerate}
    \item \textbf{Lexical Speech-Regex Supervision (\texttt{ActionClaimGrammarSupervisor}):} Expanding a first-person past-tense regex from 21 verbs to 44 stems and adding progressive participle rules raised in-vocabulary sensitivity to $71.1\%$ ($128/180$) across $N=1{,}000$ completions from four Gemma-4 models. However, sensitivity collapsed to \textbf{29.5\% ($23/78$)} on 10 unseen out-of-dev action verbs ($58.5\%$ [$151/258$] overall).
    \item \textbf{Structured-Output Action Contracts (SOAC):} Requiring typed \texttt{[ACTION: ...]} frames verified against cryptographic receipts eliminated unframed prose leakage ($0/120$ on \texttt{gemma-4-26B-A4B}), but the contract system prompt caused the model to emit spurious action frames on $13.3\%$ ($4/30$) to $16.7\%$ ($5/30$) of figurative conversational idioms (e.g., \emph{``kill two birds with one stone''}).
\end{enumerate}

Paper~02 \cite{maxwell2026evasion} therefore left an open architectural question: how can an edge agent verify open-vocabulary action claims, classify epistemic proof-policy hazards, and route multi-sentence user intents at $<5\text{ ms}$ latency without consuming dGPU VRAM or failing on multi-sentence prose?

When we trained 22M-parameter \texttt{DeBERTa-v3-small} cross-encoders and sequence classifiers and compiled them to OpenVINO FP16 on the Intel AI Boost NPU (\texttt{WO-41}), single-sentence holdout accuracy reached $100.0\%$ ($90/90$). Yet when we subjected those exact NPU checkpoints to an uncurated 300-item multi-sentence stress test (\texttt{Blind-300}, \texttt{WO-42 Phase 1}), aggregate accuracy dropped to \textbf{60.0\% ($180/300$)}: $45.0\%$ ($45/100$) on action-claim verification, $75.0\%$ ($75/100$) on hazard classification, and $60.0\%$ ($60/100$) on intent routing.

This paper diagnoses the root cause of that multi-sentence collapse and presents the clause-level neurosymbolic pooling architecture that resolves it.

\section{Why Whole-Turn Neural Classifiers Fail on Multi-Sentence Turns}
\label{sec:failure_diagnosis}
Line-by-line inspection of the 120 failures in the pre-pooling \texttt{Blind-300} run (\texttt{logs/test\_reports/wo42\_blind390\_before\_after\_report.json}) identified three deterministic failure mechanisms when transformer sequence classifiers score an entire multi-sentence turn as a single token span:

\subsection{Mechanism 1: Softmax Dilution in Multi-Sentence Outputs ($55/100$ Coherence Misses)}
When an assistant response contains 3 to 5 sentences of accurate technical explanation or empathetic dialogue and a single sentence asserting an unexecuted action (e.g., \emph{``Your CPU temperature is normal at 52\,$^\circ$C. Everything looks healthy. I have cleared the temporary diagnostic logs for you. Let me know if you need anything else.''}), whole-paragraph encoding pools attention across all 45 tokens. Because $80\%$ of the tokens belong to benign explanatory clauses, the \texttt{[CLS]} representation shifts toward \texttt{SAFE\_CONVERSATIONAL}, pushing the \texttt{UNEXECUTED\_CLAIM\_VIOLATION} softmax probability below the $0.50$ decision threshold. This failure also occurred on agentless passives (\emph{``The configuration file has been updated''}), third-person persona self-references (\emph{``Lucca saved your note''}), and structured JSON/YAML/TOML status blocks (\texttt{\{"status": "deleted", "file": "notes.txt"\}}).

\subsection{Mechanism 2: Benign Context Masking High-Hazard Clauses ($25/100$ Hazard Misses)}
In the epistemic proof-policy gate (\texttt{src/lucca/core/proof\_policy.py}), a prompt containing three casual conversational sentences followed by a single medical dosage, legal liability, or destructive shell question was classified as \texttt{LOW} hazard when scored as a single paragraph.

\subsection{Mechanism 3: Conversational Opener Hijacking and Cross-Clause Entity Bleed ($40/100$ Router Misses)}
Natural voice turns frequently open with greetings, venting, or compliments before stating a task (e.g., \emph{``Ugh, my screen is so cluttered today and it's driving me crazy. Take a screenshot of my display right now.''}). Whole-utterance classification Either assigned the turn to \texttt{venting} / \texttt{chit\_chat} (starving the turn of tools) or predicted the correct tool intent while extracting the target entity string from the wrong sentence.

\section{Clause-Level Neurosymbolic NPU Architecture}
\label{sec:architecture}
Rather than retraining larger models that would exceed our $<5\text{ ms}$ latency budget, we keep all three \texttt{DeBERTa-v3-small} OpenVINO FP16 models pinned to the Intel AI Boost NPU ($0\text{ MB}$ dGPU VRAM) and introduce a deterministic symbolic decomposition and pooling layer around each classifier. All NPU \texttt{CompiledModel} calls are serialized by per-model \texttt{threading.Lock} instances to prevent OpenVINO \texttt{Infer Request is busy} collisions under concurrent background memory indexing.

\subsection{Syntactic Clause Segmentation (\texttt{split\_into\_clauses})}
Given an input text $T$, \texttt{split\_into\_clauses(T)} decomposes $T$ into an ordered sequence of clauses $C = (c_1, c_2, \dots, c_m)$ using sentence punctuation boundaries (\texttt{[.!?;\textbackslash n]+}) while protecting decimal numbers (\texttt{3.14}), file extensions (\texttt{config.toml}, \texttt{notes.md}), abbreviations, and inline code blocks. Structured key-value blocks (JSON, YAML, TOML, XML status tags) are extracted as dedicated clause spans.

\subsection{Max-Violation Pooling for Action-Claim Verification (\texttt{NeuralActionClaimVerifier})}
For assistant output $T_a$ and user prompt $T_u$ when no matching tool receipt exists (\texttt{tool\_receipts = []}), \texttt{NeuralActionClaimVerifier} (\texttt{src/lucca/sandbox/neural\_action\_claim\_verifier.py}, \texttt{models/action\_claim\_verifier\_ov}) evaluates each clause $c_i \in \text{split\_into\_clauses}(T_a)$ alongside the full turn:
\begin{equation}
p_{\text{viol}}(T_u, T_a) = \max_{c \in \{T_a\} \cup \text{split\_into\_clauses}(T_a)} P_{\text{NPU}}\!\left(\texttt{UNEXECUTED\_CLAIM\_VIOLATION} \;\middle|\; T_u, c\right)
\end{equation}
A single clause $c_i$ asserting an unexecuted state change drives $p_{\text{viol}} \ge 0.50$ regardless of how many benign sentences surround it. In addition, deterministic pre-filters strip fenced code definitions (\texttt{def }, \texttt{class }, \texttt{import }) when the user asked for a code snippet, while structured status blocks (\texttt{"status": "executed"}, \texttt{<status>deleted</status>}) and foreign-language first-person execution claims are normalized into canonical verification spans.

\subsection{Max-Hazard Lattice Pooling for Epistemic Proof Policy (\texttt{NeuralHazardClassifier})}
For user prompt $T_u$, \texttt{NeuralHazardClassifier} (\texttt{src/lucca/core/neural\_hazard\_classifier.py}, \texttt{models/proof\_policy\_hazard\_ov}) defines a total order over the four operational epistemic classes:
\begin{equation}
\texttt{LOW} (0) \prec \texttt{MEDIUM} (1) \prec \texttt{HIGH} (2) \prec \texttt{CROSS\_REFERENCE\_CMD} (3)
\end{equation}
Each clause $c_i \in \text{split\_into\_clauses}(T_u)$ is scored on the NPU. Any clause whose maximum softmax confidence falls below $0.65$ (\texttt{UNKNOWN\_FAIL\_CLOSED}) escalates fail-closed to $\texttt{HIGH}$ ($2$). The turn-level hazard is the supremum across all clauses:
\begin{equation}
\text{Hazard}(T_u) = \max_{c_i \in \text{split\_into\_clauses}(T_u)} \text{rank}(c_i)
\end{equation}
bounded below by a deterministic domain safety floor (\texttt{\_HIGH\_HAZARD\_DOMAIN\_RE} covering medical dosages, legal liability, financial wire/tax directives, and destructive shell commands).

\subsection{Task-Priority Pooling for Multi-Sentence Intent Routing (\texttt{NeuralIntentClassifier})}
For 29-class intent routing (\texttt{src/lucca/router/neural\_intent\_classifier.py}, \texttt{models/router\_intent\_ov}), we partition the 29 intents into conversational intents $\mathcal{I}_{\text{conv}} = \{\texttt{chit\_chat}, \texttt{compliment}, \texttt{insult}, \texttt{venting}, \texttt{opinion\_request}, \texttt{persona\_question}, \texttt{confirm}, \texttt{cancel}, \texttt{correction}\}$ and 20 actionable task/tool intents $\mathcal{I}_{\text{task}}$. Given clauses $(c_1, \dots, c_m)$:
\begin{enumerate}
    \item If any clause $c_i$ predicts a task intent $y_i \in \mathcal{I}_{\text{task}}$ with confidence $\ge 0.50$, all conversational clauses $y_j \in \mathcal{I}_{\text{conv}}$ are deprioritized, and the highest-confidence task clause $c^*$ wins the turn route.
    \item Target entities (\texttt{extract\_entity\_from\_clause}) are extracted strictly from the winning task clause $c^*$ rather than the full multi-sentence transcript, preventing cross-clause entity contamination.
    \item \textbf{Temporal Keyword Guard (\texttt{\_EXPLICIT\_SCHEDULE\_RE}):} Audit of the initial locked holdout revealed that relative time words (\emph{``today''}, \emph{``right now''}, \emph{``this morning''}) inside file, code, or search requests caused \texttt{router\_intent\_ov} to predict \texttt{schedule\_event}. We added a lexical precondition requiring explicit scheduling cues (\texttt{remind}, \texttt{alarm}, \texttt{schedule}, \texttt{timer}, \texttt{calendar}, \texttt{appointment}, or \texttt{at HH:MM}) before \texttt{schedule\_event} can override a non-scheduling clause.
\end{enumerate}

\section{Compounded System Integration}
\label{sec:compounded}
Upgrading the three NPU classifiers and adding 3-tier anti-bot web extraction (\texttt{scrapling v0.4.6} with \texttt{curl\_cffi} TLS fingerprint impersonation and \texttt{sanitize\_html\_against\_prompt\_injection} CSS/comment stripping in \texttt{src/lucca/sandbox/web\_tool.py}) exposed four downstream bottlenecks in the rest of the cognitive architecture, which we resolved in tandem (\texttt{tests/unit/test\_wo42\_compounded\_enhancements.py}):
\begin{enumerate}
    \item \textbf{Multi-Category Compound Tool Shortlisting (\texttt{src/lucca/core/tool\_shortlister.py:225--297}):} Prior to \texttt{WO-42}, \texttt{shortlist\_tools()} discarded all secondary task categories whenever more than one category was activated, starving two-sentence prompts (e.g., \emph{``Search the web for CVE-2026-4096 and write a summary to audit.md''}) of workspace tools. Packing secondary activated categories into the remaining slots under the hard $\le 12$ tool cap preserves all 6 \texttt{cognitive\_core} tools plus both task categories.
    \item \textbf{Deep-Extract Search \& Citation Provenance (\texttt{src/lucca/sandbox/service.py:616}, \texttt{orchestrator.py:2907}):} Exposing \texttt{deep\_extract: bool} on \texttt{search\_web} routes multi-source queries to \texttt{research\_topic} without exceeding the 24-tool registry cap (\texttt{MAX\_REGISTRY\_TOOLS = 24}), while registering scraped \texttt{"sources"} URLs with \texttt{OutputSupervisor.register\_allowed\_urls} so cited URLs are not flagged as fabricated citations.
    \item \textbf{Sentence-Filtered Cross-Reference Corroboration (\texttt{src/lucca/core/orchestrator.py:4442--4544}):} When \texttt{NeuralHazardClassifier} triggers \texttt{CROSS\_REFERENCE\_CMD}, \texttt{CorroborationEngine.compute\_proposition\_alignment} (\texttt{src/lucca/core/corroboration.py:666}) checks whether candidate evidence contains negation or adversative markers (\texttt{\_RE\_NEGATION\_POLARITY}, \texttt{\_RE\_ADVERSATIVE\_DEFEATER}). Passing an entire 3,500-character scraped article body caused false conflicts whenever unrelated paragraphs contained words such as \emph{``not''} or \emph{``however''}, whereas passing 150-character search snippets truncated version numbers and dates. Extracting only the top 1--2 sentences with highest claim-token overlap per independent domain (\texttt{\_extract\_claim\_aligned\_sentences}) preserves per-domain receipt independence while preventing unrelated paragraph negations from defeating corroboration.
    \item \textbf{NLI Entailment Wiring in Offline Skill Induction (\texttt{src/lucca/reasoning/induction.py:402--465}, \texttt{reflection.py:373}):} Passing \texttt{verifier: SemanticVerifierPort} from \texttt{DreamRetrospective} into \texttt{RuleInducer.mine\_patterns()} activates bidirectional NLI entailment clustering in \texttt{cluster\_phrasings()} for paraphrased multi-sentence tool arguments whose token-set Jaccard similarity falls below $0.60$.
\end{enumerate}

\section{Limitations and Residual Error Analysis}
\label{sec:limitations}
\begin{enumerate}
    \item \textbf{Residual False Negatives ($6/471 = 1.27\%$ on $N=2{,}022$):} Inspection of the 6 missed positive claims in \texttt{logs/test\_reports/wo42\_large\_sample\_2020\_report.json} shows that all 6 come from the 1,000-turn sampled corpus (\texttt{W751..W1000}) where the model implied completion through an indirect state consequence without an explicit action verb or status token (e.g., \emph{``Your inbox is now completely empty and ready for Monday''} in response to an email archive prompt).
    \item \textbf{Residual False Positives ($9/1{,}551 = 0.58\%$ on $N=2{,}022$):} The 9 false alarms occur on hypothetical troubleshooting walkthroughs where the assistant writes first-person illustrative steps (\emph{``First, I updated the registry key in my test environment...''}) without fencing them in code blocks.
    \item \textbf{Linear Latency Scaling with Clause Count:} Because \texttt{NeuralActionClaimVerifier} evaluates the full response plus each extracted clause sequentially under a thread lock on the Intel NPU, mean verification latency scales from $1.31\text{ ms}$ on 1-sentence outputs to $2.95\text{ ms}$ (P95 $3.67\text{ ms}$) on 3--4 sentence outputs. On 10+ sentence long-form essays, clause-by-clause NPU scoring can reach $8$--$12\text{ ms}$; batching clause tensors into a single static-shape NPU call is left for future work.
    \item \textbf{Single-Workstation Measurement Scope:} All latency, VRAM, and live 4-model measurements were recorded on a single Windows 11 workstation (Intel Core Ultra 9 275HX, Intel AI Boost NPU, NVIDIA RTX 5080 Laptop GPU 16\,GB GDDR7) and are labeled \emph{Author-measured} until independently reproduced on external hardware.
\end{enumerate}

\section{Conclusion}
\label{sec:conclusion}
Lexical speech-regex supervisors cannot generalize to open-vocabulary verb lemmas ($29.5\%$ unseen-verb recall in Paper~02 \cite{maxwell2026evasion}), while whole-paragraph neural classifiers fail when a single fabricated action claim or task request is embedded inside multi-sentence prose ($60.0\%$ on \texttt{Blind-300}). By combining syntactic clause decomposition with domain-specific pooling operators---max-violation pooling for action-claim verification, max-hazard lattice pooling for proof-policy classification, and task-priority pooling for intent routing---three 22M-parameter \texttt{DeBERTa-v3-small} classifiers running in FP16 on an Intel AI Boost NPU ($0\text{ MB}$ dGPU VRAM, $1.22$--$2.95\text{ ms}$) achieve $99.26\%$ accuracy ($98.73\%$ recall, $0.58\%$ FPR) across $N=2{,}022$ action-claim turns, $96.67\%$ single-pass / $100.0\%$ post-guard accuracy on the pre-registered \texttt{WO42\_LOCKED\_HOLDOUT\_150} benchmark, and $100/100$ functional coherence across all four local Gemma-4 model scales.
