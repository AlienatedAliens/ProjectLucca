## 2. Sub-Step 1.2 — Belnap 4-Valued Epistemic Probe Wiring & NLI `UNCERTAIN` Fail-Closed Remediation

### 2.1 Exact Problem
1. [`src/lucca/workers/verifier.py:340-433`](../../src/lucca/workers/verifier.py) (`VerifierWorker.verify`) and `SemanticVerifierPort.check_consistency` return `NLIVerdict.UNCERTAIN` (or `VerifierResult(label=VerifierLabel.NEUTRAL, degraded=True)`) when the NPU model is unavailable or logit confidence is below threshold.
2. Ten downstream call sites only branch on `== NLIVerdict.CONTRADICTION` (or `== VerifierLabel.CONTRADICTION`) and silently treat `UNCERTAIN` / `degraded=True` as non-contradictory pass-through.
3. Meanwhile, [`src/lucca/memory/latent_probe.py`](../../src/lucca/memory/latent_probe.py) (`403` lines) already implements the complete Belnap-Dunn four-valued lattice (`BelnapValue.TRUE`, `BelnapValue.FALSE`, `BelnapValue.NEITHER` $\bot$, `BelnapValue.BOTH` $\top$) and `BelnapLatentInvestigator`, but has **zero callers in `src/lucca/`**, while [`src/lucca/core/cascade.py:138-245`](../../src/lucca/core/cascade.py) contains a `108`-line duplicate copy of the Belnap functions (`belnap_negation`, `belnap_meet_k`, `belnap_join_t`, `belnap_meet_t`, `pool_evidence`) that is also never called.

### 2.2 Exact Change Manifest
| File & Line Range | Action |
| :--- | :--- |
| `src/lucca/core/cascade.py:138-245` | Delete the duplicate inline Belnap lattice definitions (`-108` lines) and import `BelnapValue`, `BelnapLatentInvestigator`, `belnap_negation`, `information_meet`, `information_join`, `truth_meet`, `truth_join`, `combine_evidence` from `lucca.memory.latent_probe` (aliasing `belnap_meet_k = information_meet`, `belnap_join_t = truth_join`, `belnap_meet_t = truth_meet`, `pool_evidence = combine_evidence` for test back-compat). |
| `src/lucca/memory/latent_probe.py` | Add helper method `BelnapLatentInvestigator.evaluate_nli_verdict(verdict_or_result: object, has_lexical_conflict: bool = False) -> BelnapValue`:<br>• `CONTRADICTION` $\to$ `BelnapValue.BOTH` ($\top$, active conflict when prior evidence exists) or `BelnapValue.FALSE`.<br>• `ENTAILMENT` $\to$ `BelnapValue.TRUE`.<br>• `UNCERTAIN` or `degraded=True` $\to$ `BelnapValue.BOTH` ($\top$) if `has_lexical_conflict` is True, else `BelnapValue.NEITHER` ($\bot$, epistemic ignorance). |
| `src/lucca/core/memory_commit_service.py:605-645` | In `commit_transcript` / `maybe_extract_facts` conflict check: when NLI returns `UNCERTAIN` (or `BelnapValue.NEITHER` / `BelnapValue.BOTH`) against an existing active memory slot on the same `(subject, predicate)` with a different object, **fail closed** by routing the candidate memory to `REVIEW_QUEUE` (quarantine) rather than silently committing it as non-contradictory. |
| `src/lucca/core/belief_service.py:215-260` | In `check_contradictions`: when NLI returns `UNCERTAIN` (`BelnapValue.NEITHER`) on a candidate belief revision that lexically diverges from an existing held belief, queue a non-destructive clarification update via `BelnapLatentInvestigator` rather than silently dropping the contradiction check. |
| `src/lucca/core/cascade.py:1510-1545` | In `EpistemicSearchCascade`: use `BelnapLatentInvestigator` to pool evidence across substrates. When NLI verification returns `UNCERTAIN` (`BelnapValue.NEITHER`), apply an explicit epistemic confidence discount (`* 0.65`) and mark the synthesis trace with `belnap_state="NEITHER"`; when two substrates conflict (`BelnapValue.BOTH`), surface both citations explicitly rather than silently picking one. |
| `src/lucca/core/corroboration.py:475-520` & `src/lucca/core/orchestrator.py:1590-1625` | In `compute_proposition_alignment` and `_evaluate_step_corroboration`: when `verifier.check_consistency` returns `degraded=True` or `UNCERTAIN`, do **not** grant semantic alignment (`is_aligned = False`) and propagate `uncertain_verification = True` so uncorroborated claims cannot pass as NLI-verified. |
| `tests/unit/test_bdi_belnap_fail_closed.py` (new test module) & `tests/test_static_gates.py` | Add unit tests injecting a degraded/uncertain `VerifierWorker` across `MemoryCommitService`, `BeliefService`, `EpistemicSearchCascade`, and `CorroborationEngine`, proving `UNCERTAIN` fails closed to `REVIEW_QUEUE` / confidence discount. Add static AST gate `test_no_nli_uncertain_fail_open_consumers()` in `tests/test_static_gates.py`. |

### 2.3 Expected Runtime Differences When Online
- **Memory & Belief Integrity Under NPU Contention:** Previously, if the NPU verifier timed out or returned a low-margin `UNCERTAIN` verdict while a user or web page introduced a conflicting fact, Lucca treated `UNCERTAIN` as "no contradiction" and overwrote/committed the fact. With `BelnapLatentInvestigator` online, `UNCERTAIN` ($\bot$) on a conflicting slot routes to `REVIEW_QUEUE` quarantine, and genuine multi-source conflicts ($\top$) produce an explicit "Source A states X while Source B states Y" clarification instead of silent overwrite.
- **Line Count Delta:** Net reduction of `~60` lines (deleting the `108`-line duplicate in `cascade.py` while adding ~48 lines of wiring).

## 3. Sub-Step 1.3 — Wiring Win32 Handle Security (`win32_security.py`) & Transactional Staging DAG (`git_dag.py`) into `SafeFileTool`

2. [`src/lucca/memory/git_dag.py`](../../src/lucca/memory/git_dag.py) (`518` lines) implements `GitStagingDAG` and `WorkspaceTransactionManager` (atomic multi-file staging, cycle detection, `.py` AST syntax validation before commit, and automatic rollback on failure), but `SafeFileTool` and `SandboxService` never call it (`0` imports in `src/lucca/`).

### 3.2 Exact Change Manifest
| File & Line Range | Action |

Add `SafeFileTool.execute_transaction(operations: list[dict[str, object]])` backed by `WorkspaceTransactionManager`, and route `SafeFileTool.apply_patch` through `WorkspaceTransactionManager` so failed hunks or syntax-invalid Python patches automatically roll back to the pre-patch file state. |

### 3.3 Expected Runtime Differences When Online
- **Zero TOCTOU Race Window on Windows File Operations:** Any symlink, NTFS junction, or hardlink swapped in after path string validation is caught at the Win32 kernel handle level (`GetFileInformationByHandle`) before a single byte is read or truncated.
- **Transactional Patch Rollback:** When Lucca applies a code patch (`apply_patch`) that fails mid-way or introduces a Python `SyntaxError`, `WorkspaceTransactionManager` automatically restores the original file bytes instead of leaving a half-written file in the workspace.
