Their arg schemas must match the existing Pydantic validators in `rpc.py` (`ListDirArgs`, `SearchTextArgs`, and the `run_python` `code`/`timeout` signature at [`file_tool.py:292`](../src/lucca/sandbox/file_tool.py)). Their risk levels come from `TOOL_RISK_MAP`.
- Remove `launch_app` from `get_tool_definitions`, from `get_default_tool_schemas` ([`lifecycle.py:42-58`](../src/lucca/reasoning/lifecycle.py)), from `TOOL_DEFINITIONS` in `prompt_builder.py`, and from every prompt-facing enum. Keep `config/tool_whitelist.toml` untouched on disk.

- `inbox_handoff` and `clipboard_read`: declare **nothing** in this phase. They are deferred; the spec's "✅ exists" for `inbox_handoff` was wrong.

**T1.2 — `invoke_skill` dispatch tool.**
Register one native tool: `invoke_skill(skill_id: str, args: dict = {})`, `target: self`. Dispatch contract:
1. Resolve `skill_id` in the rule registry. Not found → structured error `unknown_skill`.
2. Rule must be `ACTIVE` **and** have `expose_as_tool: true` in its metadata. Otherwise → structured error `skill_not_exposed`.
3. `skill_id` must appear in the **current turn's category manifest** (T1.4). Otherwise → structured error `skill_not_in_manifest` (this is the negative-test path).
4. Execute the rule's plan through the existing plan executor (same path as a `:when` match). Plan actions inherit their own class gates at the dispatcher.

**T1.3 — Static category menu in the frozen prefix.**
Add to the system-prompt static block (byte-stable): a 7-entry category menu — `cognitive_core`, `information`, `host_perception`, `companion`, `self`, `host_readonly`, `shared` — one line each: name + one-sentence description. No per-turn content in this block.

**T1.4 — Category manifest via Prompt Frontier Suffix.**
Implement `format_category_manifest(category: str | None, skills: list[SkillMeta]) -> str` in `prompt_builder.py`, composing with `format_stance_suffix` at the tail of the frontier user message (same injection point, [`prompt_builder.py:811`](../src/lucca/brain/prompt_builder.py)). Manifest format: `[SKILLS category=<name>: skill_id — one-line description (args: summary); ...]`. Empty category or no exposed skills → emit nothing (suffix stays stance-only).
Category selection: deterministic mapping from the heuristic router's existing `intent` + `entities` to a category (a plain dict in `router/heuristic.py`, no LLM call). No mapping → no manifest that turn (the LLM fallback, requesting a category in text, is **not** implemented in this phase — log a `category_miss` telemetry event instead; fallback comes later).

**T1.5 — Retire BOTH flat skill catalogs (rewritten per C3).**
1. Remove the `format_skill_tools` call from `get_all_tool_definitions` ([`prompt_builder.py:800-806`](../src/lucca/brain/prompt_builder.py)) and delete the function.
2. Remove the `skill_<id>` append loop from `CapabilityRegistry.get_tool_definitions` ([`capabilities.py:270-293`](../src/lucca/core/capabilities.py)).
3. Rewrite `get_capabilities_manifest` ([`capabilities.py:315-328`](../src/lucca/core/capabilities.py)) so `tools` is derived from `get_tool_definitions()` names, not a hardcoded list. This drops `launch_app` and the phantom `get_task_status`/`list_tasks`/`cancel_task` entries (advertised today but not callable — note this pre-existing inconsistency in the worklog; if async-task tools are meant to be callable, that is a separate ticket, not this phase). Skills are reported under `reasoning_pathways`, never under `tools`.
4. Update every test that referenced `skill_<rule_id>` tool definitions.

**T1.6 — Registry cap + schema freeze.**
Assert at startup: registry ≤ 16 tools (**expect exactly 9** at this gate — see §0.0). Render the full chat prompt for 10 synthetic turns spanning ≥3 different categories; assert the byte content of everything before the final user message is identical across all 10; assert the suffix differs only in the manifest portion.

## 3. Phase 3 — L1a: Skill Package Format + Admin CLI
