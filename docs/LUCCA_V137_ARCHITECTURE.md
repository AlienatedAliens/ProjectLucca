## 1. Executive Summary & Design Principles

Project Lucca is an uncensored, local personal systems companion and research engineer designed to execute entirely on consumer hardware with zero external telemetry, cloud APIs, or recurring subscriptions.

Version 1.37.0 ratifies the **Compound Neurosymbolic Edge Architecture with Counterexample-Guided Inductive Synthesis (CEGIS)**, solving three fundamental failure modes of standalone edge language models:

1. **Deterministic Domain Routing (Sub-Millisecond Heuristic Dispatch):**  
   Language models are inherently prone to arithmetic drift, hallucinated multi-hop spatial tracking, and unbounded combinatorial branching. Version 1.37.0 wires a unified, sub-millisecond dynamic router (`src/lucca/router/heuristic.py`) that identifies problem topology and dispatches queries directly to dedicated symbolic tools (`sympy_sandbox` in container, `container_world` for spatial tracking, `z3_smt` for constraint satisfaction) in $<1\,\text{ms}$, bypassing probabilistic hallucination.

2. **Autonomous Multi-Turn CEGIS Self-Repair (`PythonCEGISEngine`):**  
   Code and mathematical synthesis generated by edge models frequently encounter runtime exceptions (`ValueError`, `NameError`, `ZeroDivisionError`). Version 1.37.0 introduces an automated, in-container feedback loop that captures standard error tracebacks and pipes them into Turn 2 for immediate repair. This yields a **$2\times$ empirical lift** on AIME 2024 competition math (20% $\to$ 40%) and rescues 8–16% of failing programs on CRUXEval-Input with **strictly zero regressions** across all evaluated tiers.

3. **Persistent Sandbox Bridge (`PersistentDockerWorker`):**  
   Eliminates the legacy ~472 ms WSL2 process spawn penalty by maintaining a long-lived bidirectional stdio bridge to `lucca-toolsrv --loop` inside an unprivileged Docker container (`lucca-file-sandbox`). Tool execution latency drops to **<2 ms** (<22 ms total roundtrip), enabling real-time conversational turnaround.

4. **Host-Defensive Protection with Uncensored Operator Sovereignty:**  
   Resolves the distinction between host safety and model censorship. Lucca enforces strict, deterministic host and container defenses against hostile prompt injections, disk wipes (`del /s /q`, `rm -rf`), Docker socket escapes, credential theft, and memory envelope forgery (20/20 attacks intercepted in 0.02 ms). Concurrently, conversational output censorship is explicitly deactivated (`tts_safety_guard_mode = "off"`). Lucca is an uncensored sovereign companion; user queries are the user's responsibility, and safety guards exist exclusively to protect the user's machine and environment.

5. **Sub-Second Real-Time Voice Synthesis (Kokoro-82M):**  
   End-to-end voice interaction achieves an average turnaround of **783.6 ms** with Kokoro-82M generating pristine 24kHz audio at a Real-Time Factor (RTF) of **0.201** (~$5\times$ faster than real-time playback).

## 3. Dynamic Neurosymbolic Heuristic Router (`D-ROUT-02`)

The router (`src/lucca/router/heuristic.py`) classifies incoming transcripts in $<1\,\text{ms}$ using compiled regex lexicons, conformal intent calibration, and model-tier awareness:

```
[User Transcript] ──► Normalization & Semantic Match
                            │
       ┌────────────────────┼─────────────────────────┐
       ▼                    ▼                         ▼
 [Emergency Reflex?]  [Domain Match?]           [Uncertain / LLM]
       │                    │                         │
  Action: RULE         Action: LLM               Action: LLM
  Tier: REFLEX         Tier: FULL_LOOP           Tier: FULL_LOOP
  Latency: <1ms        Solver Dispatch:          Thinking Mode:
  - Stop execution     - SymPy Sandbox           - 12B: Direct (no collapse)
  - Mute audio         - ContainerWorld (Spatial) - Edge: Thinking (+40pp lift)
  - Abort process      - Z3 SMT (Constraints)
```

### 3.1 Domain Solver Mappings
1. **Mathematical Sandbox (`sympy_sandbox`)**:  
   Queries matching `MATHEMATICAL_SYMPY_PATTERN` (equations, systems, integrals, polynomials, arithmetic, competition problems) are routed with `thinking_mode="direct"` to synthesize clean Python/SymPy scripts executed inside the Docker container.
2. **Spatial Relocation (`container_world`)**:  
   Queries matching `CONTAINER_WORLD_PATTERN` (object transfer, multi-hop tracking, epistemic theory-of-mind) are routed to the deterministic `ContainerWorld` state tracker, resolving multi-hop container lookups in 0.0 ms.
3. **Combinatorial Constraints (`z3_smt`)**:  
   Queries matching `COMBINATORIAL_SMT_PATTERN` (SAT solving, logic puzzles, Zebra puzzles) are routed to Z3 formalization in Python sandbox.
4. **Tier-Adaptive Thinking Modes**:
   - **Gemma 4 12B Unified**: Forces `thinking_mode="direct"` on deductive tasks to prevent the 36.7% overthinking collapse.
   - **Gemma 4 E4B / E2B Edge**: Forces `thinking_mode="thinking"` on soft logic to capture the +40 pp reasoning lift (23% $\to$ 63%).

## 4. CEGIS Multi-Turn Counterexample Self-Repair Architecture

When edge models synthesize code or mathematical proofs, first-turn execution frequently fails due to off-by-one errors, missing imports, or type errors. `PythonCEGISEngine` (`src/lucca/reasoning/cegis_python.py`) provides an autonomous repair loop:

```
[Problem] ──► Turn 1: Synthesize Script ──► Docker Container Execution
                                                    │
                                     ┌──────────────┴──────────────┐
                                     ▼                             ▼
                               [Exit Code 0]                 [Exception / Crash]
                                     │                             │
                               Output Verified               Capture Traceback
                                     │                             │
                                   PASS              Turn 2: Traceback Ingestion
                                                                   │
                                                            Synthesize Fix
                                                                   │
                                                      Docker Container Execution
                                                                   │
                                                      PASS (Rescued) or FAIL
```

## 5. Defensive Security & Operator Sovereignty Charter

### 5.1 Host & Container Defense Invariants (`D-SEC-05`)
Safety in Project Lucca is architected to protect the operator and host filesystem from unauthorized destruction and prompt injections:
- **Destructive Command Interception**: Absolute rejection of destructive disk commands (`del /s /q`, `rm -rf`, format drives, path traversal).
- **Container Isolation**: Sandbox container executes with `--network none`, `--read-only`, non-root user (`1000:1000`), bounded CPU/memory cgroups (768 MiB), and blocked Docker socket access.
- **Credential Exfiltration Barriers**: Post-fetch write barriers prevent tools from transmitting private keys, tokens, or local notes across network boundaries.
- **Cryptographic Memory Provenance**: Two-stage HMAC-SHA256 signature verification over all stored memory triples prevents memory injection, HMAC forgery, and replay attacks.
- **Empirical Scorecard**: **20 / 20 (100.0%) attacks intercepted**, 0 escapes, 0.02 ms average defense latency (`logs/test_reports/defensive_security_benchmark_1791810503.json`).

### 5.2 Operator Sovereignty & Uncensored Output Policy
- Conversational output censorship is explicitly deactivated (`tts_safety_guard_mode = "off"`).
- The operator possesses full sovereignty over inquiries and conversational topics.
- Safety boundaries exist exclusively to defend the host machine, container integrity, and private memory substrate against adversarial tampering.
